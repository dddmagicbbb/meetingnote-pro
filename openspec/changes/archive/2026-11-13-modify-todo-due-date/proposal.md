# Proposal

## Why

할 일 기한이 「다음 주 금요일」 · 「이번 주 안」 같은 받아쓴 글자로만 저장되어, 기한이 지났는지 사람이 회의 날짜를 떠올려 직접 계산해야 한다. 화면의 기한 지남 표시도 「어제 · 지난주 · 지난달」 세 글자에만 반응해 실제로 날짜가 지난 일은 잡지 못한다.

## What Changes

- 할 일에 날짜 기한 `due_date` 를 더한다. 원래 글자 `due_text` 는 지우지 않고 그대로 남긴다
- 서버가 기한 글자를 **회의 날짜 기준**으로 날짜로 바꾼다 (직접 등록한 할 일은 등록한 날 기준)
  - 「다음 주 금요일」 → 회의 다음 주의 그 금요일
  - 「다음 주까지」 → 회의 날짜 7일 뒤
  - 「이번 주 안」 · 「이번 주까지」 → 회의가 있는 주의 금요일
  - 그 밖에 뜻이 하나로 정해지는 표현(내일 · N일 뒤 · X요일 · N월 N일 · 월말 등)은 design.md 의 변환표대로
  - 못 정하면 `due_date` 는 비우고 글자만 남긴다
- 기한 글자를 고치면(`PUT /api/todos/{id}`) 날짜도 다시 계산한다
- 기한 지남 판정을 글자 대조에서 날짜 비교로 바꾼다 - `due_date` 가 오늘보다 앞이고 완료가 아니면 붉은 띠. 날짜가 없으면 판정하지 않는다
- 칸반 · 내 정보 · 상세 화면에 날짜를 보이고 원래 글자도 함께 보인다
- 할 일 정렬을 status 다음 `due_date`(빈 값은 뒤) 순으로 바꾼다
- 이미 저장된 할 일은 서버 시작 때 열을 추가하고 같은 규칙으로 한 번 채운다

범위 밖:
- 날짜 고르기 달력 입력 - 이번에는 글자를 고치면 서버가 다시 계산하는 방식만
- 기한 알림 · 푸시 (정의서 범위 외 그대로)
- Gemini 프롬프트 변경 - 날짜 계산은 서버의 정해진 규칙으로만 한다

## Capabilities

### New Capabilities

(없음)

### Modified Capabilities

- `todo`: 기한 날짜 변환 · 기한 표시 요구사항 추가, 팀 할 일 목록(필드 · 정렬) · 담당자 배정(기한 글자 수정) · 기한 지남 표시 · 직접 등록 요구사항 변경
- `meeting`: 결정사항과 할 일 저장 모양 - 회의록 저장 때 할 일 기한을 회의 날짜 기준으로 날짜로 바꾸는 내용 추가

## Impact

- DB: `todos.due_date` (DATE, NULL 허용) 열 추가. 기존 로컬 DB 는 시작 때 자동으로 열 추가 + 채움
- API: 할 일 응답(목록 · 단건 · 회의록 단건의 todos · 내 할 일)에 `due_date` (`YYYY-MM-DD` 또는 null) 추가. 요청 모양은 그대로
- 코드: `backend/` 에 기한 변환 모듈 추가, `models.py` · `routers/todos.py` · `routers/meetings.py` · 시작 시 이관. `frontend/api.js` 의 `isLate` 와 날짜 표시, `todos.html` · `detail.html` · `profile.html` 의 기한 칩
- 테스트: 변환표 단위 테스트, API 테스트, e2e 기한 지남 확인 갱신
